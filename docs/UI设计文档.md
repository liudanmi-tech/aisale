# AIGC 投放平台 · UI 设计文档（v2，结合技术方案）

日期：2026-10-12
实现：`web/`（Vite + React 19 + React Router 7 + Ant Design 6 + Tailwind 4 + Zustand，与 infinite-canvas 一致）+ `api/`（FastAPI）。接口前缀均为 `/api/v1`。早期单文件原型见 `docs/prototype.html`。

本文档把 PRD、技术方案和界面对齐到同一张表上：每个页面写清楚**路由、布局、组件、调用的接口、对应的数据表、审核点**，研发可以直接按页面拆任务。

---

## 1. 设计结论

1. **核心页面是「项目画布」**：左侧 Agent 对话、右侧无限画布。剧本、视频、评测都是画布上的节点，双击进入详情页，不单独占导航。
2. **Agent 只能通过一组画布工具改画布**，每次改动都是「计划卡 → 画布预览 → 确认 → 逐步落地 → 可撤销」。
3. **每个模块产出结论后都停在审核门**：节点状态变为「待审核」，进入审核中心；通过后工作流才继续（对应 Temporal Signal）。
4. **风格借鉴 LibTV**：深色主题、无限画布 + 节点工作流、Agent 入口、作品卡片网格。卡片上的数字换成投放指标（CTR、完播率、CPA），不是点赞。
5. **第一版为领导演示服务**：主链路 9 步全部可点通，Meta / X、浏览器 Agent 实时画面等先做占位。

## 3. 核心链路（原型右下角「核心链路」面板逐步打勾）

| 步骤 | 用户在哪操作 | 画布变化 | 后端 | 审核点 |
| --- | --- | --- | --- | --- |
| 1 选爆款，点「一键洗剧本」 | `/ads` 详情抽屉 | 新增或选中「爆款」节点，跳到画布并自动发指令 | `GET /ref-ads/{id}` | 爆款入库前已审 |
| 2 Agent 写剧本 | `/p/p1` 左侧对话 | 计划卡 + 紫色虚线框预览 → 执行后出现剧本节点（生成中 → 待审核） | `POST /scripts:generate`，script 子工作流 | 剧本 |
| 3 审核剧本 | `/review` 或剧本编辑器顶栏 | 节点变「已通过」，下游连线由虚变实 | `POST /reviews/{id}:decide` → Signal | — |
| 4 生成视频 | 对话「生成视频」 | 为已通过的剧本各新增视频节点，计划卡显示费用 | `POST /creatives:generate`（Seedance 异步 + 回调） | 视频 |
| 5 审核视频 | 审核中心 / 视频工作室 | 同上 | 同上 | — |
| 6 40 Agent 评测 | 对话「跑评测」，评测页看过程 | 新增评测节点，显示最高分 | `POST /evaluations` | 评测结论 |
| 7 投放方案并下发 | 对话「生成投放方案」→ `/delivery` | 新增投放节点；审核通过后在投放中心点「下发」 | `POST /delivery/plans`、`:launch`（TikTok API） | 投放方案 |
| 8 数据回收与优化 | 自动 | 新增数据节点、优化节点 | metrics / optimizer 服务 | 优化建议 |
| 9 迭代再生成 | `/data` 采纳建议 | 回到画布，Agent 提出迭代剧本计划，确认后形成第二轮 | script 子工作流 | 剧本（第二轮） |

**链路规则**：上游未通过审核，Agent 拒绝执行下游指令，并在对话里给出待审核节点的芯片（原型里在还没有已通过的视频时说「跑评测」即可看到）。

## 4. 项目画布（核心页面）

### 4.1 布局

| 区域 | 尺寸 | 内容 |
| --- | --- | --- |
| 左侧 Agent 面板 | 默认 30%，最小 340px，最大 520px；可收起为 56px | 头部：收起按钮、Agent 名称、状态（空闲 / 执行中 / 等待确认 / 等待审核）；中部：对话流与计划卡；底部：选区上下文条、快捷指令、输入框 |
| 右侧画布 | 剩余宽度 | 点阵背景；右上工具栏（整理 / 撤销 / 放大 / 缩小 / 复位）；左下图例与操作提示 |
| 窄屏（< 900px） | 上下排列 | Agent 面板在上（48vh），画布在下 |

### 4.2 节点规范

| 节点 | 图标字 / 颜色 | 列位置 | 双击去向 | 对应后端对象 |
| --- | --- | --- | --- | --- |
| 爆款 | 爆 / 橙 | 第 1 列 | 爆款详情抽屉 | ref_ad |
| 卖点 | 卖 / 青 | 第 1 列 | 资产库 | selling_point |
| 人群包 | 群 / 紫 | 第 1 列 | 资产库 | audience |
| 剧本 | 剧 / 品牌紫 | 第 2 列 | 剧本编辑器 | script |
| 视频 | 视 / 蓝 | 第 3 列 | 视频工作室 | creative |
| 评测 | 评 / 黄 | 第 4 列 | 评测页 | evaluation |
| 投放 | 投 / 绿 | 第 5 列 | 投放中心 | ad |
| 数据 | 数 / 蓝绿 | 第 6 列 | 数据看板 | ClickHouse 聚合 |
| 优化 | 优 / 品红 | 第 7 列 | 数据看板 · 优化建议 | optimization_action |

节点卡片：宽 168、高 66 起；头部为图标字 + 标题，中部一行摘要，底部为状态徽章（+ 评测得分）。

| 状态 | 徽章 | 画布表现 | 来源 |
| --- | --- | --- | --- |
| 未开始 | 灰 | — | 节点刚创建 |
| 生成中 | 紫 | 边框流光 + 「Agent 正在编辑」标签 | 子工作流 Activity 运行中 |
| 待审核 | 黄 | 下游连线为灰色虚线 | review_task.status = wait |
| 已通过 | 绿 | 下游连线为实线 | decide = pass |
| 已驳回 | 红 | Agent 自动按意见重做，版本号 +1 后回到待审核 | decide = reject |
| 投放中 | 蓝 | — | ad.status = live |
| 计划预览 | 紫色虚线框 | 不可拖动；连线为紫色虚线 | Agent 计划，尚未执行 |

### 4.3 画布交互

- 单击选中，Shift 单击多选；选中后左下输入框上方出现「已选 N 个节点」上下文条，指令只作用于选区。
- 拖动节点调整位置；拖动空白处平移；滚轮以光标为中心缩放（0.4–2 倍）。
- 双击节点进入详情页（见 4.2）。
- 对话里的节点芯片：悬停时画布高亮该节点、其余变淡；点击后画布平移居中并选中。

### 4.4 Agent 指令与画布动作

| 指令类型 | 示例 | 画布动作 | 是否需确认 |
| --- | --- | --- | --- |
| 写剧本 | 「用 @爆款 #12 给小商贩写 3 个续航剧本」「给学生写 2 个拍照剧本」 | 新增 N 个剧本节点，连到爆款与人群包 | 需要（可在计划卡里调数量） |
| 生成视频 | 「生成视频」（作用于选区或全部已通过剧本） | 每个已通过剧本新增 1 个视频节点 | 需要，显示费用 |
| 评测 | 「跑评测」 | 新增 1 个评测节点，连到所有已通过视频 | 需要 |
| 投放方案 | 「生成投放方案」 | 新增投放节点；真正下发在投放中心 | 需要 |
| 整理 | 「整理画布」 | 按节点类型分列重新排布 | 免确认，可撤销 |
| 查询 | 「哪个视频预测 CTR 最高？」 | 只读回答 + 高亮节点 | 免确认 |
| 总结 | 「总结进度」 | 只读回答 | 免确认 |
| 撤销 | 「撤销上一步」或工具栏「撤销」 | 整组回滚上一次 Agent 操作（含整理） | 免确认 |

### 4.5 执行计划卡

1. Agent 收到指令后先在对话中出计划卡：步骤清单、费用、是否进入审核；画布同步显示紫色虚线框预览。
2. 计划卡上可调数量、取消或执行；发新指令会让旧计划失效。
3. 执行后步骤逐条打勾，节点依次「生成中 → 待审核」，并自动生成审核单。
4. 整组操作记一条历史，可一键撤销。

### 4.6 防误操作

- Agent 没有删除节点的工具，只能建议删除。
- 花钱的步骤（视频生成、投放下发）一律显示费用并需人工点击；投放下发只能在投放中心由人点。
- Agent 不能替人通过审核。
- 上游未通过时，Agent 拒绝执行下游指令并指出卡在哪个节点。

### 4.7 Agent 画布工具协议（对应技术方案第 5、8 节）

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `query_canvas` | filter（类型、状态、选区） | 读取画布快照：节点 ID、类型、编号、状态、选区 |
| `create_node` | type, title, data, position? | 新建节点，position 缺省时按列自动摆放 |
| `update_node` | node_id, patch | 修改节点数据（如某一镜文案） |
| `connect` | from, to | 新建连线 |
| `layout` | strategy（by_type / by_audience） | 自动布局 |
| `select` / `focus` | node_ids | 设置选区 / 平移居中 |
| `run_node` | node_id, action | 触发对应子工作流（生成剧本、视频、评测、投放方案） |

每次规划产出一个操作补丁（patch），前端先渲染预览，用户确认后服务端应用：

```json
{
  "patch_id": "pt_20261012_0031",
  "base_version": 42,
  "summary": "写剧本",
  "cost": {"credits": 0.2, "usd": 0},
  "needs_review": true,
  "ops": [
    {"op": "create_node", "temp_id": "g1", "type": "script", "data": {"sp": "续航", "audience_id": "aud_1"}},
    {"op": "connect", "from": "n_ad12", "to": "g1"},
    {"op": "connect", "from": "n_aud1", "to": "g1"},
    {"op": "run_node", "node_id": "g1", "action": "generate_script"}
  ]
}
```

`base_version` 已过时（例如用户刚手动改了同一节点）时，服务端拒绝应用，Agent 重新规划。

## 5. 其他页面

### 5.1 工作台 `/`
- 顶部大输入框「一句话开始投放项目」，下方示例指令芯片；回车后进入项目画布，并把这句话发给 Agent。
- KPI 行：本周花费、CPA、CTR、完播率，带环比。
- 左侧本周飙升爆款（点击打开爆款详情），右侧待办（按模块的待审数）与最近项目。

### 5.2 爆款库 `/ads`
- 筛选：市场、卖点（后续加：品牌、钩子类型、平台、时间范围、排序）。
- 卡片：9:16 封面、左上市场、右上爆款分、底部品牌 / 投放天数 / CTR / 完播率；估算值加虚线下划线和「估」字。
- 详情抽屉（右侧 640px）：预览、指标表、创意 DNA 标签、分镜时间轴、评论洞察；底部「加入画布」「一键洗剧本」。

### 5.3 剧本编辑器 `/p/:id/script/:nodeId`
- 顶栏：返回画布、标题、状态、版本 · 市场 · 语言；待审核时右侧显示「通过 / 驳回」。
- 左栏：参考爆款与本剧本设定。中栏：分镜表（镜、时长、画面、本地语言口播、中文对照），单元格可直接编辑，每镜有「重写」。右栏：合规自检和「对这个剧本下指令」。

### 5.4 视频工作室 `/p/:id/video/:nodeId`
- 顶栏：模型 Seedance · 9:16 · 1080p · 时长 · 预估费用；审核按钮。
- 左栏：资产（角色、产品素材库、BGM、品牌包）。中栏：分镜条（每镜可选 AI 生成 / 产品素材库 / 数字人，可单独重生成）和四轨时间线。右栏：成片预览与自动质检。
- 产品镜头默认用官方素材，不用 AI 生成。

### 5.5 评测页 `/p/:id/eval/:nodeId`
- 左栏：播放器、进度、逐秒流失曲线、「播放评测过程」。
- 中栏：40 个虚拟用户头像矩阵（每行 8 个）：紫色为观看中，灰色为划走，绿色为看完，手指图标为点击 CTA；悬停显示画像。
- 右栏：结论表（视频、得分、预测 CTR、完播率），入选名单、建议人群、主要问题。

### 5.6 投放中心 `/delivery`
- 投放方案卡：平台与账户、广告结构、定向、预算与出价、护栏、上线前自检。
- 方案待审核时可在卡上直接通过；通过后才可点「下发到 TikTok」。
- 执行日志逐条显示 API 步骤；API 不支持的步骤由浏览器 Agent 在云虚拟机中执行（后续加实时画面小窗）。
- 投放列表：素材、状态、花费、CTR、完播率、CPA。

### 5.7 数据看板 `/data`
- KPI、近 7 日花费与 CPA、创意元素热力图（钩子 × 人群，CTR 相对大盘）、评测校准（预测与实测的排序相关系数）。
- 优化建议卡：待审核时显示「采纳 / 驳回」；采纳后回到画布，Agent 提出迭代剧本计划，闭环进入第二轮。

### 5.8 审核中心 `/review`
- 三栏：左侧按模块筛选（带待审数）；中间队列；右侧详情（Agent 结论、依据、打开节点）。
- 操作：通过（A）、驳回（R，必填理由，理由作为 Agent 重做的输入）、修改后通过。
- 驳回后节点自动「生成中 → 待审核」，版本号 +1。

### 5.9 资产库与设置
- 资产库：卖点库（参数、合规表述、优先级）、人群包、角色资产、产品素材、本土化词库。
- 设置：TikTok 已连接；Seedance 待填 API Key；第三方情报待采购；Meta / X 二期；自动优化规则阈值；免确认指令范围。

## 7. 通用状态

| 状态 | 表现 |
| --- | --- |
| 空状态 | 一句话 + 下一步入口（如投放中心无方案时，引导回画布说「生成投放方案」） |
| Agent 执行中 | 节点流光边框 + 「Agent 正在编辑」；计划卡逐步打勾 |
| 等待确认 | Agent 状态显示「等待确认」，计划卡有「执行 / 取消」 |
| 异常 | 红色边框 + 原因 + 「重试」「转人工」；平台接口失败时展示平台原始错误码 |
| 危险操作 | 二次确认，写明影响范围与金额 |

## 8. 演示脚本（约 10 分钟，对应原型）

1. 工作台（1 分钟）：KPI、待办、飙升爆款。
2. 爆款库（1 分钟）：筛「尼日利亚 · 拍照」，打开爆款 #12，点「一键洗剧本」。

4. 审核（1 分钟）：审核中心按 A 通过；演示驳回一个，看 Agent 自动重做。
5. 视频（1 分钟）：说「生成视频」，看费用确认；打开视频工作室。
6. 评测（1.5 分钟）：说「跑评测」，打开评测页播放 40 头像；回画布问「哪个视频预测 CTR 最高？」。
7. 投放（1 分钟）：说「生成投放方案」，投放中心通过方案、下发，看执行日志。
8. 数据与优化（1.5 分钟）：数据看板采纳优化建议，回到画布确认迭代计划，闭环进入第二轮；最后「整理画布」看全貌。
