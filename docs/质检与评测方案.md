# 视频质检与 40 人评测方案

流程：剧本通过 → 分镜 → 选角置景 → **关键帧 → 关键帧质检** → 图生视频 → **成片质检** → 人工审核 → **40 人评测** → 投放方案（合规检查）。

## 1. 质检（`api/app/qc.py`）

每一镜分两段检查，每项结果是 pass / warn / fail，并写一句原因。

| 标签 | 检查项 | 怎么查 | 判定 |
|---|---|---|---|
| 商品 | 颜色、摄像头模组形状 / 数量 / 排列、屏幕形态、机身比例、无竞品标志 | 多模态模型对照商品实拍图逐项检查 | 商品镜头从严：任何一项 fail 就整镜 fail；画面里没有手机也 fail。**商品镜头一律要人工确认** |
| 人物 | 人脸相似度 | OpenCV YuNet 检测 + SFace 特征，和定妆照算余弦相似度。0.363 是 OpenCV 推荐的同一人阈值，低于 0.30 判「没找到正脸」 | 不像只提示 warn（侧脸、背影检测不到）；同一角色匹配到多张脸提示「分身」 |
| 人物 | 服装、发型、主要角色人数 | 多模态模型对照定妆照 | 背景路人、群演不算多出来的人 |
| 画质 | 手 / 脸畸形、肢体穿模、残留线稿、拼图分屏 | 多模态模型按清单检查 | 拼图、分屏判 fail |
| 画质 | 乱码、中文字符、可读店招 | 多模态模型 | 手机自身的品牌 logo 可以有 |
| 画质（仅成片） | 9:16 画幅、时长、黑帧、冻帧、模糊、闪烁 | ffprobe / ffmpeg（blackdetect、freezedetect）、OpenCV（拉普拉斯方差、亮度突变） | 画幅或时长不对判 fail，其余 warn |
| 剧本 | 是否符合这一镜的描述和景别 | 多模态模型 | 最多 warn，只提示，不触发重画；字幕、CTA、logo 在后期加，不扣分 |

成片质检从片段里均匀抽 3 帧（首、中、尾），再做人脸和清单检查，看前后帧有没有变脸、商品有没有变形。

**自动重做**：关键帧 fail 时，把问题清单作为修改意见重画，最多 2 次；成片 fail 时重新生成 1 次。还不合格的镜头用最后一版，标红交给人。

**结果存放**：每镜 `tasks[i].qc`（包含 status、checks、issues、manual_confirm、attempts）；视频节点 `data.qc` 存汇总，包括「n/4 镜通过」、自动重做次数、需人工确认的镜头，也写进审核单。

**画布**：每镜下方显示 `商品✓ 人物✓ 画质⚠ 剧本✓`，点开可看每项原因、人脸相似度和关键帧。视频节点头部显示汇总。

**依赖**：
- `opencv-python-headless`。
- 人脸模型首次使用时从 Hugging Face 下载（约 39MB），存到 `MEDIA_DIR/models`；下载失败时人脸检查标为「未执行」。
- ffmpeg：macOS 用 `brew install ffmpeg`；没装时成片规格检查标为「未执行」。

设置页的「视频质检」可以选用的模型，默认 `google/gemini-2.5-flash`，必须能看图。

### 实测（尼日利亚 · 停电续航剧本）

质检抓到的都是真问题：
- 店招上出现中文字符；
- 一镜生成成了三格拼图；
- 商品镜头的摄像头模组和实拍图不一致；
- 背景里有和主角同一张脸的「分身」。

第一版规则过严，已按实测放宽：
- 非商品镜头里人物拿手机，不再判错；
- 背景路人不再算人数；
- 不再要求画面里出现 CTA；
- 背对镜头的角色不再判「没找到」。

关键帧生成的提示词也补了规则：
- 必须是一个瞬间的单张照片；画面描述里有时间段时，只挑一个瞬间；
- 人物和街景要像当地；
- 手机外观照抄实拍图。

另外放宽了两条规则：
- 手机屏幕、本子上的零星小字只提示，不判错；
- 群体角色（如「市场小商贩们」）不按 1 人计数。

调整后第二轮的结果：
- 拼图、中文店招都没再出现，商品镜头的圆形摄像头模组和实拍图一致；
- 4 镜中，1 镜通过、2 镜待看、1 镜不合格（服装不一致、疑似分身），交给人工审核。

## 2. 40 人评测（`api/app/panel.py`）

- **40 个独立 Agent**：每个虚拟用户单独调用一次模型，最多 8 个并发，彼此看不到对方的回答，避免一次调用里 40 人「商量好」给出整齐的分布。
- **画像**：市场、人群、年龄、城市、职业、在用手机、收入、爱看的内容、刷视频习惯、日常语言。
- **逐镜观看**：每个 Agent 拿到每镜的关键帧（缩到 384px 宽）、时间段和口播，逐镜评这一镜比平时刷到的手机广告更能让自己看下去吗（-2 到 +2），写下当时的想法，最后评点击意愿（也是 -2 到 +2）和 5 个维度（5 分 = 和平时的广告差不多）。
- **为什么不让模型直接说看不看完**：第一版让 Agent 直接回答「继续看 / 划走 / 点击」，实测 40 人里 40 人看完、39 人点击，连「对广告很反感」的人也点了。模型扮演用户时系统性偏乐观，所以改成模型只给相对判断，再用基准概率换算并抽样：
  - 第 1 镜（前 3 秒）继续看的基准概率，按刷视频习惯取 0.2–0.55；之后每镜 0.8；看完的人点击的基准概率 6%。
  - 相对评分换成倍数：-2 → ×0.3，-1 → ×0.6，0 → ×1，+1 → ×1.3，+2 → ×1.6，概率上限 0.95。
  - 用视频 id 做随机种子，同一条视频重复评测结果一致。
  - 效果：所有人都评「差不多」时，约 12% 的人看完；都评 +2 时约一半看完。
- **汇总**：
  - 总分：五维平均分 × 10 和完播率（完播 50% 及以上算满分）各占一半。五维分偏高，不能单独用来选片。
  - 逐镜留存：每镜开始时还在看的比例。
  - 逐镜相对评分：哪一镜拖后腿。
  - 主要问题：流失最多的一镜，加上评价最低的一镜和它收到的差评原话。被基准流失率抽中划走的人不一定不满意，所以只引用差评。
- **实测**（停电续航剧本）：40 个 Agent 约 20 秒评完，完播 40%，1 人点击，逐镜留存 100 / 45 / 42 / 40。相对评分最低的是第 3 镜产品特写（+0.7），没有一镜被多数人评得比平时的广告差。
- **点击率未校准**：页面上的 CTR 是 40 个模拟用户的点击意向换算出来的，`calibrated=false`，标「未校准」。上面的基准概率和倍数都是行业经验值，拿到传音历史投放的真实分镜留存和 CTR 后，回归校准这些参数。
- **退回模拟**：少于 30 个 Agent 有回答时，整体退回模拟结果，引擎显示 `simulated`。

## 3. 合规

- **演员肖像授权**：上传真人照片时必须勾选或确认授权条款，后端没收到 `consent=true` 返回 400。确认时间和条款文本记在素材的 `data.consent` 里。AI 生成的演员不需要授权。
- **AIGC 标识**：投放方案里 `aigc_label=true`，页面显示「AIGC 内容标识已开启」。TikTok Marketing API 的具体字段，接真实下发时再按官方文档确认。
- **投放前检查**：投放方案的检查项里加了「演员肖像授权」，项目里每个用了真人照片的演员都必须有授权记录。
